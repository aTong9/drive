# RoadLens：风景与创作手账整改方案

日期：2026-09-19。范围：当前 React 应用的 11 个主要页面，以及地点发现 → 路线研究 → 拍摄计划 → 视频项目 → 后期 → 发布资料的链路。

本文保留最初整改要求及后续执行记录。共享视觉与主要功能整改已陆续落地，具体实现和验收证据见第8节；早期「待实施」是制定方案时的状态，不代表当前全部未做。完整深层视觉验收与最后逐项审计仍未结束。不涉及上线发布。

## 1. 视觉方向与本轮落地

方向：宫崎骏动画般的自然、安静、日常旅行感。用乡野公路、水彩山峦、积云、树木和纸质手账承载氛围；专业参数仍保持规整、准确、易读。

| 组成 | 本轮实施 | 后续细化 |
| --- | --- | --- |
| 晴日手账 | 米白 `#f6f3e9` 背景、纸白 `#fffdf6` 卡片、森林绿 `#41684e` 交互色、深墨绿文字 | 按页面整理全部遗留硬编码颜色 |
| 林间夜色 | 深绿 `#172c29` 背景、苔绿面板、浅黄绿选中态；保留既有主题偏好，新用户默认晴日 | 深层教程与长表格逐组件核对对比度 |
| 插画 | 原创乡野公路横幅；地点库清晰展示，其余页面降低透明度以保证阅读 | 后期、音乐、设备可分别补工作室、林间唱片、相机手账插画；不需要每张卡片放插画 |
| 品牌 | 幼芽印章、衬线英文标识、「风景与创作手账」副标、在路上标记 | 与现有 PWA 图标继续保持一致 |
| 卡片与控件 | 纸色面板、淡边框、柔和阴影、手账式非对称圆角、绿色选中态 | 信息密集区域按优先级提升字号 |
| 排版 | 标题使用本机宋体/衬线字体，正文延续系统字体，数字保持规整 | 信息标题、正文、辅助文案建立统一尺度 |
| 交互 | 保留焦点边框、已有弹窗焦点管理、移动底栏；卡片仅轻微悬浮反馈 | 不加入持续飘叶、视差或遮挡参数的装饰 |

插画属于界面装饰，不替代真实地点照片或来源证据；地图瓦片、现场照片、调色示意图保持原有内容与色彩。

实现归属：`src/journal.css` 为新主题入口，`src/styles.css` 的已有常用背景与橙色透明度接入共享变量。`src/main.tsx` 加载主题。旧变量 `--orange` 暂保留名字以兼容既有组件，其语义现在是主要交互色。

## 2. 页面职责和整改清单

优先级：P1 = 影响任务可靠性或关键操作；P2 = 信息结构与效率优化；P3 = 后续视觉完善。下表是最初的问题基线、整改要求和验收标准；当前进展见第8节，不以局部通过代替整项验收。

| 页面 | 当前功能与入口 | 问题或改进机会 | 整改动作 | 优先级与验收 |
| --- | --- | --- | --- | --- |
| 地点库 | 默认入口；地区、城市、景观筛选；地点/路线切换；照片、天气、来源、实地核验导入导出 | 页面同时承担发现、路线目录、核验维护；与探索页重复筛选；地区和选中状态主要在组件内 | 保留默认入口，定位为「发现地点」；默认展示筛选和结果，将核验备份收进维护区；保持返回前的查询、分页、选中地点；地点→路线统一调用同一打开动作 | P2：查看详情再返回，地区、关键词、页码与滚动位置可恢复；来源核验与实地核验仍分开 |
| 探索路线 | 目的地、主拍法、时段、时长；地图、驾车结果、GPX、旅行拍摄篮、路线详情、创建计划 | App 的 `currentRegion` / `destination` 与 Store 路线筛选分属不同状态；其他页面直接 `selectRoute` 不能清空 App 筛选，目标路线可能被当前筛选排除 | 建立统一「打开指定路线」动作，显式处理原筛选与目标路线；展示拍摄时长与驾车时间差异；地图/定位失败保留文本路线 | P1：先选 A 城，再从计划或相机页打开 B 城路线，必须显示 B 城目标；分享、列表、关联路线路径行为一致 |
| 拍摄计划 | 按日期排序的卡片；状态推进；建项目、查看路线、删除 | 当前页面只能变更状态，不能直接修改日期和目标；删除立即执行；排序列表的名称易让人期待真正的月历 | 先补原地编辑日期/目标和可撤销删除；保留轻量日期列表，不先造复杂月历；已拍摄与已发布明确由用户确认 | P1：改日期后正确重排且刷新保留；误删可撤销；不误改已关联项目 |
| 相机参数库 | 设备/场景预设；参数词典、最多三套对比、决策工具、收藏、自定义参数、现场模式、导出 | 复核确认：无结果时已有详情隐藏保护，但原空状态缺少恢复入口；本轮已补。自定义参数使用数字回退，仍需审查错误提示 | 已补无结果恢复按钮；后续按「设备→场景→关键值→高级说明」组织；对数值范围与 ISO 上下界进行明确校验 | P1：不匹配的搜索不能显示旧方案为匹配结果；非法值不保存且有字段级说明 |
| 后期工作台 | 总览、项目执行、教程中心、工具箱；DaVinci 八工作区、剪映、FCP、调色预设、对比、诊断、词典 | 执行任务与学习资料同页，约 1,247 行组件；项目管理和视频项目页存在衔接成本；深层模式仍有遗留视觉样式 | 保持现有工作区导航，把「执行清单」和「查教程」分清；教程按真实软件工作区归类；之后按现有模式拆文件，先抽纯展示部分 | P2：从项目进入其执行上下文；三种软件的教程入口稳定；输入色彩空间、工作空间和交付标签不被视觉改造混淆 |
| 音乐素材库 | 单曲、专辑、平台授权、钢琴创作者；场景、来源、时长、授权风险；试听/下载外链、署名复制 | 发现音乐与视频项目里的音乐许可台账没有直接衔接；四类内容使用不同筛选集合，需明确适用范围；部分复制动作缺少失败反馈 | 保持现有任务筛选与单曲长时长筛选；增加带曲名、来源、链接的「记入项目」动作，授权结论仍须逐曲确认；统一复制成功/失败提示 | P2：添加后项目能追溯来源，且不会自动勾选授权完成；来源与作者不混为同一实体 |
| 创作者研究 | 标杆频道与普通人方向双入口；检索、分类、研究展开；收入模型估算 | 内容量大，收益排序可能掩盖创作适配；选题研究尚未直接变成项目草案；组件约 910 行 | 默认按兴趣、拍摄条件和内容形态选择；收益估算放辅助位置并保留假设；支持把选题笔记带入项目，引用原案例 | P2：能从方向产生可执行的首条选题；估算不会被展示成实际收入；展开研究有稳定返回位置 |
| 长片制作指南 | 类型、规模/存储估算、准备度、章节排期、流程、覆盖模型、剪辑和交付指南 | `formatId`、时长、天数、码率、准备勾选均为组件 `useState`，切页卸载后重置；复制简报未捕获失败 | 将项目草案纳入版本化本地持久化或关联现有视频项目；保留显式重置；为复制失败提供提示 | P1：填写一套参数并勾选，切页/刷新可恢复；改变类型按明确规则处理准备度 |
| 视频项目 | 计划生成或 JSON 导入；镜头、出发包、素材接收、音乐许可、后期质检、发布、复盘 | 页面约 1,099 行，操作区很多；与 Dashboard、后期和上传页共享上下文，但入口分散 | 成为制作阶段的唯一项目事实入口；顶部固定当前阶段与下一步；章节导航直达各操作区；其余页面引用项目而非复制状态 | P2：从项目可带上下文去后期/音乐/发布并返回；导入导出往返保持数据；不因页面拆分丢失记录 |
| 创作工作台 | 下次拍摄简报、旅行研究续接、当前项目、核验覆盖、条件推荐、后期参考 | 与视频项目页有信息重叠；空数据时统计占比高 | 定位为「今天继续什么」：按待办优先显示下一次拍摄、当前项目、研究进度；把累计统计后置；空状态引导找地点 | P2：有计划/无计划、有项目/无项目都提供一个明确下一步；不再成为第二个项目编辑器 |
| 上传参数 | 项目/频道版本选择；双语标题、说明、标签和发布检查；分发建议；复制资料 | `projects.find(...) ?? projects[0]` 会让空 `projectId` 回退到首个项目，已有项目时「通用模板」不能真正独立；复制并非上传发布 | 明确空选项代表通用模板，只对失效非空 ID 使用回退；保留「准备资料」定位；已上传、平台处理、HDR确认、已发布单独记录 | P1：至少一个项目时切通用模板，输出不再带该项目资料；切回项目正确恢复；不会把复制成功当发布完成 |

## 3. 信息架构

本轮保留地点库作为默认入口，保留手机「地点、探索、计划、更多」底栏。快捷导航已覆盖全部 11 页，并支持同时搜索页面名称、描述、英文页面 ID 和路线。

快捷导航现在按任务分组：

1. **出发前 · 寻找与准备**：地点库、探索路线、拍摄计划、相机参数库、创作者研究。
2. **制作中 · 留住风景**：视频项目、视频后期工作台、音乐素材库、长片制作指南。
3. **发布与复盘 · 分享旅程**：YouTube 上传参数、创作工作台。

后续考虑把「上传参数」统一命名为「发布资料」，但应同步页面标题、导航、说明与测试，避免出现多个指向同一功能的名称。Dashboard 保留续接功能，不强行作为启动首页。

## 4. 实施顺序

### 第一步：视觉与入口（本轮已实施）

- 全站共享晴日/夜色配色、手绘横幅、品牌与卡片细节。
- 修正本轮实际看到的地点选中态、天气面板、音乐卡片、相机预设和后期总览的浅色背景问题。
- 导航统一分组，补工作台搜索；自动化检查覆盖所有页面唯一归组、中文/英文/描述搜索与无匹配结果。
- 桌面与手机检查，保护真实图片和地图内容。

### 第二步：任务可靠性（待实施）

建议顺序：统一路线打开动作 → 上传通用模板 → 相机输入校验 → 长片草案持久化 → 计划编辑/删除恢复。

每个修复先写一个能复现实际问题的小测试，再改共享入口，不在每个调用页面分别补条件。持久化字段若新增，必须跟随已有 Store 版本和迁移机制。

### 第三步：页面职责收敛（待实施）

- 地点与探索：分别负责发现与行程决策，避免重复操作。
- 视频项目：保存制作事实；后期、音乐、上传消费同一项目上下文。
- 创作者/长片：输出选题或草案，能接入制作链路。
- 统一跨页面返回时的查询、分页和滚动恢复；在确有需要时再引入 URL 页面状态，而非更换整个框架。

### 第四步：结构整理与深层视觉（待实施）

- `src/styles.css` 约 20,715 行，逐页面把仍存在的硬编码颜色改为语义变量，删除被替代的重复规则；不要再追加一套主题层。
- 将后期、项目、音乐、创作者中的独立展示区按已有业务边界拆出；数据仍通过 services 获取。
- 全部深层教程、比较表、表单、错误状态和含真实项目数据的页面做逐项视觉验收。
- 不增加路由框架、组件库、动画库、CMS 或数据库，只为已确认的问题增加必要代码。
